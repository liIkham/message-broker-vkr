### 1\. rabbit.py — отправитель сообщений

Этот файл выполняет роль producer-а. Он формирует уведомление, подключается к RabbitMQ, создаёт durable-очередь notifications и публикует туда сообщение в JSON-формате. Сообщение отправляется как persistent, чтобы снизить риск потери при перезапуске брокера.









* *import json*

Нужен, чтобы превратить Python-словарь в JSON.



Например Python-словарь:

{"event": "test\_notification"}



превращается в строку JSON:

{"event": "test\_notification"}







* *import os*

Нужен, чтобы читать переменные окружения.

RABBITMQ\_HOST=localhost







* *import pika*

pika — это Python-библиотека для работы с RabbitMQ.

Без неё Python не сможет подключиться к брокеру.









* Функция отправки сообщения : *def publish\_notification(message: dict) -> None:*



Это функция, которая принимает сообщение в виде словаря.
-> None означает, что функция ничего не возвращает. Она просто выполняет действие — отправляет сообщение.







* *host = os.getenv("RABBITMQ\_HOST", "localhost")*

Здесь программа узнаёт, где находится RabbitMQ.

Она пытается прочитать переменную окружения RABBITMQ\_HOST.



Если переменной нет, берёт значение по умолчанию:

localhost



Простыми словами:

Подключаемся к RabbitMQ на этом же компьютере.





* *connection = pika.BlockingConnection(pika.ConnectionParameters(host=host))*

Создаётся подключение к RabbitMQ.

BlockingConnection — простой синхронный способ подключения.



Простыми словами:

Python открывает соединение с RabbitMQ, как будто звонит на почтовое отделение и говорит: “я хочу отправить письмо”.





* *channel = connection.channel()*

Создаётся канал внутри подключения.



Важно:

connection — это соединение с RabbitMQ;

channel — рабочий канал, через который уже отправляются команды.



Простая аналогия:

connection — это телефонный звонок, channel — конкретный разговор внутри этого звонка.







* *channel.queue\_declare(queue="notifications", durable=True)*

Создаётся очередь notifications, если её ещё нет.



durable=True означает:

Очередь должна сохраниться после перезапуска RabbitMQ.



То есть если RabbitMQ перезапустится, сама очередь не исчезнет.



Важно: durable=True сохраняет очередь, но для сохранения самих сообщений ещё нужен delivery\_mode=2, который ниже.







* *body = json.dumps(message).encode("utf-8")*

Тут сообщение готовится к отправке.



Разбиваем:



*json.dumps(message)*

превращает словарь Python в JSON-строку.



*.encode("utf-8")*

превращает строку в байты.



Почему байты?

Потому что RabbitMQ передаёт тело сообщения как набор байтов.



Простыми словами:

Мы упаковали сообщение в формат, который RabbitMQ может передать.





* Главная строка отправки сообщения(снизу)

*channel.basic\_publish(*

&#x20;   *exchange="",*

&#x20;   *routing\_key="notifications",*

&#x20;   *body=body,*

&#x20;   *properties=pika.BasicProperties(delivery\_mode=2),*

*)*



Она говорит RabbitMQ:

Отправь вот это сообщение в очередь notifications.



Разбор:



* change=""

Простыми словами:

Отправляем напрямую в очередь.





* routing\_key="notifications"

Это имя очереди, куда отправляется сообщение.





* body=body

Это само сообщение.





* properties=pika.BasicProperties(delivery\_mode=2)

delivery\_mode=2 означает persistent message.



Простыми словами:

Сообщение должно сохраняться на диск, чтобы не потеряться при перезапуске RabbitMQ.



В связке:

durable=True

delivery\_mode=2



получается:

очередь сохраняется;

сообщение сохраняется.







* finally:
* &#x20;   connection.close()

После отправки соединение закрывается.

Это важно, чтобы не оставлять открытые подключения.







* *test\_message = {*

&#x20;   *"event": "test\_notification",*

&#x20;   *"source": "cli",*

&#x20;   *"text": "RabbitMQ publish test",*

*}* 





Создаётся тестовое сообщение.



Поля:



event — тип события;

source — источник сообщения;

text — текст сообщения.





* *publish\_notification(test\_message)*

Вызывается функция отправки.







* *print("Test message published to notifications queue")*



Просто вывод в терминал:

Сообщение отправлено.























### ***2. consumer.py — обработчик сообщений***



Этот файл делает больше:



подключается к RabbitMQ;

слушает очередь notifications;

получает сообщения;

если сообщение нормальное — обрабатывает;

если ошибка — делает retry;

после 3 ошибок отправляет в DLQ.









* *import json*

Нужен, чтобы читать JSON-сообщение из RabbitMQ и превращать его обратно в Python-словарь.







* *import os*

Нужен для переменных окружения: host, port, user, password





* *import time*

Нужен для задержки между повторными попытками.



Вот эта строка использует time:

*time.sleep(delay)*





* import pika

Библиотека для работы с RabbitMQ.







* Настройка задержек retry

RETRY\_BACKOFF\_SECONDS = {

&#x20;   1: 1,

&#x20;   2: 3,

&#x20;   3: 5,

}



Это словарь задержек.



Он означает:

перед первой повторной попыткой подождать 1 секунду;

перед второй — 3 секунды;

перед третьей — 5 секунд.



Это называется backoff.



Простыми словами:

Если обработка сломалась, не надо долбить систему сразу. Лучше подождать и попробовать ещё раз.











* Функция подключения

*def get\_connection() -> pika.BlockingConnection:*

Эта функция собирает параметры подключения к RabbitMQ из переменных окружения и создаёт соединение с брокером. Это нужно, чтобы consumer мог получать сообщения из очереди.





*host = os.getenv("RABBITMQ\_HOST", "localhost")*

*port = int(os.getenv("RABBITMQ\_PORT", "5672"))*

*user = os.getenv("RABBITMQ\_USER", "guest")*

*password = os.getenv("RABBITMQ\_PASS", "guest")*



Здесь берутся настройки подключения.



По умолчанию:

host = localhost

port = 5672

user = guest

password = guest



5672 — стандартный порт RabbitMQ для AMQP-соединений.



Важно:

15672 — веб-панель RabbitMQ;

5672 — порт, через который программы отправляют и получают сообщения.







* *credentials = pika.PlainCredentials(username=user, password=password)*

Создаются логин и пароль для подключения.





* *parameters = pika.ConnectionParameters(host=host, port=port, credentials=credentials)*

Создаются параметры подключения.





* *return pika.BlockingConnection(parameters)*

Открывается соединение с RabbitMQ.











* Функция чтения retry-count

*def \_extract\_retry\_count(properties: pika.spec.BasicProperties | None) -> int:*

Функция определяет количество уже выполненных повторных попыток обработки сообщения. Это нужно, чтобы не обрабатывать ошибочное сообщение бесконечно.





* *if properties is None or properties.headers is None:*
* &#x20;   *return 0*

Если у сообщения нет свойств или заголовков, значит попыток ещё не было.







* *value = properties.headers.get("x-retry-count", 0)*

Пытаемся достать заголовок x-retry-count.

Если его нет — берём 0.





* *try:*

&#x20;   *return int(value)*

*except (TypeError, ValueError):*

&#x20;   *return 0*



Пробуем превратить значение в число.

Если там мусор, например строка "abc", возвращаем 0.

Это защита от кривых данных.











* Функция копирования заголовков

*def \_build\_headers(properties: pika.spec.BasicProperties | None) -> dict:*

Функция получает заголовки сообщения, чтобы сохранить служебную информацию, например количество повторных попыток.









* if properties is None or properties.headers is None:
* &#x20;   return {}

Если заголовков нет — возвращаем пустой словарь.









* return dict(properties.headers)

Если заголовки есть — копируем их в обычный словарь Python.



Зачем?

Чтобы потом можно было обновить:

*headers\["x-retry-count"] = next\_retry*









* Главная функция обработки сообщения

def on\_message(

&#x20;   channel: pika.adapters.blocking\_connection.BlockingChannel,

&#x20;   method: pika.spec.Basic.Deliver,

&#x20;   properties: pika.spec.BasicProperties,

&#x20;   body: bytes,

) -> None:



Это callback-функция.



Callback — это функция, которую RabbitMQ вызывает автоматически, когда в очереди появляется сообщение.



Простыми словами:

Как только пришло сообщение, RabbitMQ вызывает on\_message.



Параметры:

channel — канал связи с RabbitMQ;

method — служебная информация о доставке;

properties — свойства сообщения, включая headers;

body — само сообщение в байтах.







* retry\_count = \_extract\_retry\_count(properties)
* headers = \_build\_headers(properties)



Сначала узнаём:

сколько уже было retry;

какие заголовки есть у сообщения.







* Основной блок обработки

*try:*

&#x20;   *payload = json.loads(body.decode("utf-8"))*



Тут сообщение превращается из байтов в Python-словарь.



body.decode("utf-8")

байты → строка.



json.loads(...)

JSON-строка → Python-словарь.







* *if payload.get("event") == "fail":*

&#x20;   *raise Exception("Simulated failure")*

Это искусственная ошибка для тестирования.



Если в сообщении:

{"event": "fail"}

то программа специально вызывает ошибку.



Зачем?

Чтобы проверить работу retry и DLQ.



На защите можно сказать:

Для проверки отказоустойчивости предусмотрен тестовый сценарий, при котором сообщение с типом fail имитирует ошибку обработки.
